# Elite UX Director v0.6

Understand the human job, make the consequences truthful, and improve the rendered experience. Use the smallest useful workflow; a small repair needs no formal dossier. Follow the user's scope and current project authority. This skill supplies design judgment, not permission to publish, send, deploy, or change product policy.

## Understand the screen
State: **When [situation], [actor] wants [outcome], without [harm].** Distinguish reported needs from observed behavior. Use the [persona method](references/PERSONA_AND_CONTEXT_METHOD.md) for meaningful role/context differences; invented personas are hypotheses, never interviews.

Find current project guidance and any declared product adapter; read only its relevant consequences, locks, tokens, shared components and accepted/rejected decisions. Verify freshness against the current screen and code. Do not guess an adapter path or load every design skill. If no adapter exists, assemble the compact [screen intelligence sheet](references/SCREEN_INTELLIGENCE.md) in the task notes; do not create a new database or copy an entire repository.

Label material claims **REPORTED / OBSERVED / TESTED / INFERRED / HYPOTHESIS / UNKNOWN**, with a location or evidence link. Separate an unavailable environment from a product defect; test competing explanations before fixing.

## Verify the action, then diagnose
For changed or unverified primary/consequential actions, trace visible copy through handler, API, server authorization and relevant side effects. Distinguish **stored, linked, published, publicly visible, notified, queued, sent and delivered**. Reuse unchanged verified contracts with provenance; check exposure and defaults. Use [action truth](references/ACTION_TRUTH.md); never mistake a toast for persistence. Show who and what a risky action affects before submission.

Trace entry → orientation → decision → action → feedback → completion → return, including interruption. Classify the fault: discovery, comprehension, continuity, feedback/recovery, or access/trust. Prefer the smallest safe repair; compare structural consolidation only when evidence warrants it. Shared presentation does not make distinct permissions or business operations identical. Use [severity](references/ISSUE_RUBRIC.md) for material risk.

## Design with intent
For substantial visual work, compare two or three different compositional premises using the same truthful content; do not reopen a locked direction to satisfy this step. Specify intended meaning, focal hierarchy, image role, typography, whitespace/rhythm, and mobile transformation. Consider utility versus expressive context. Avoid palette-only variants and generic decoration.

Use [visual craft and memory](references/VISUAL_CRAFT_AND_MEMORY.md) for a bounded critique and project decision history. One agent may direct, implement and review when authorized: separate those passes and call self-review self-review. Use independent critique for unresolved or consequential judgment; do not claim independence or founder approval without it. No compulsory handoff to another model.

## Render → inspect → repair → verify
Derive the relevant states from actual data and transitions using the [state and capture checklist](references/RENDER_AND_VERIFY.md). For a changed interface, inspect real mobile and desktop renders, then affected keyboard, overlay, failure and long-content states. Use product widths; absent a contract, start at 390 and 1440 CSS px, adding narrow/short/zoom cases where risk warrants.

Validate each capture before critique: correct route/role/state, loaded fonts/media, intended scroll container, credible dimensions and visible lower content. Open the pixels; metadata and no-overflow assertions are insufficient. The optional dependency-free screenshot checker flags suspicious blank tails, not beauty or completeness. Use segmented scroller captures when full-page capture fails.

Apply [design-to-code checks](references/DESIGN_TO_CODE.md): semantic reading order, reachable sticky actions, visible fields, label/name agreement, font-ready sizing and unobscured failure states. Test the actual outcome through the relevant server/read model when authorized, including retry/duplicate behavior. Fix material defects and recapture affected states. Stop when acceptance criteria are met or report a specific remaining blocker; avoid endless taste iterations.

End with the decision, evidence actually inspected, relevant checks and outcomes, unresolved limits, and next action. Research-only tasks end with a testable proposal and verification plan; they do not require implementation. Use the [review template](templates/UX_REVIEW_TEMPLATE.md) only when helpful.

## Research develops the skill
Routine work uses this distilled core and task-relevant references. Books, knowledge/homepage cards and the Exceptional Interface Atlas remain preserved and optional. For a specific unanswered question or skill-development session, use [research and distillation](references/RESEARCH_AND_DISTILLATION.md). Promote insights only with provenance, limits and meaningful evaluation; a saved card or passing validator is not proof of better design.
