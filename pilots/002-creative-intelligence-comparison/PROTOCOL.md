# Pilot 002 — Creative Intelligence vs Strong Frontend Baseline

**2026-11-13 · PREPARED, NOT EXECUTED**

## Research question
Does a curated Creative Intelligence direction packet improve cultural specificity, visual distinction and overall usable design quality when compared with a capable frontend designer given the same project facts, assets, time and quality requirements?

## Pilot conditions
- **A — Strong baseline:** verified product facts and tasks; same licensed assets, same content, same framework and engineering budget; standard capable frontend-design implementation.
- **B — Creative Intelligence:** identical inputs and implementer capability, plus a source-scoped creative thesis, 3 distinct concept directions, selection rationale, 2–4 tested/cited artistic mechanisms and critique rubric.

Don't weaken A deliberately. Don't hide accessibility or performance requirements from either condition. Avoid one model seeing both outputs in a way that contaminates B; record ordering and any cross-learning.

## Scope boundary
Use an **isolated Faneqo homepage sandbox**, after the founder indicates the existing Claude work is clear and authorizes design prototyping. Do not write to Faneqo production repositories. A successful pilot does not approve deployment.

## Preflight
1. Verify the latest Faneqo product truth and existing homepage rather than reusing memory or an old marketing deck.
2. Obtain approved copy, real artist/fan imagery or appropriately licensed alternatives, real navigation/CTA requirements, visual brand constraints and conversion goals.
3. Freeze the content/assets manifest and accessible baseline.
4. Create three truly different concepts, not variations of background or font color.
5. Founder selects direction B for implementation (or authorizes a preliminary blinded comparison).

## Matching conditions
- Same user tasks, copy, imagery pool, mobile/desktop widths (320, 390, 768, 1280), time and review cycles.
- Same performance constraints, image budget, WCAG-oriented keyboard/focus/reflow/reduced-motion checks.
- Same build system (Nuxt 3 with Composition API if approved), build success and basic test coverage.
- Record tool/model versions, commit hashes, dependencies, total work budget, and prompt differences.
- One baseline critique and one Lab critique may occur, but compare like stages; never compare A first draft against B after three rounds of improvement.

## Evaluation

**Independent visual/creative critique:** identify the actual cultural thesis in the page without reading its brief, composition and typography authority, photographic authenticity, differentiated visual rhythm, coherence across responsive widths, and emotional clarity. Founder review is decisive but subjective; if possible recruit 2 independent design reviewers.

**Practical web/mobile tasks:** Can a visitor identify what Faneqo is, locate the main artist action, discover price/trial details, reach relevant product areas, and trust that site imagery/claims reflect actual product? Freeze task list after product verification. Actual participants and measured observations required before claiming usability outcomes.

**Technical:** browser-console errors, keyboard tab order, visible focus, WCAG-oriented contrast, mobile scroll/reflow, reduced motion, accessible names, media loading, layout shift, SSR/hydration, measured performance if available. Record exact devices/browser/screenshot hashes and test commands.

**Evidence honesty:** report both artistic judgment and task/engineering results separately; do not collapse a six-axis rubric into a single winner score.

## Decision output template
- Design A: strengths, confirmed defects, artistic weakness, task result (tested/untested).
- Design B: strengths, confirmed defects, artistic weakness, task result (tested/untested).
- Verdict: A / B / hybrid / neither, with reasoning.
- Principle improved/refuted: exact Lab reference and revision.
- Owner decision: approved / revision requested / rejected.
- Production implication: none unless separately authorized.

## Stop conditions
Misleading product claims, unlicensed copied imagery, broken primary actions, major keyboard barriers, inconsistent evaluation budgets, invented measured outcomes, or unauthorized production changes.
