# The Design Systems Observatory

**Research increment:** 2026-11-11  
**Goal:** understand the decisions behind excellent product experience and reusable components, not collect brand styles for imitation.

## Primary reading paths
- [Apple Human Interface Guidelines](apple-hig.md) — purpose, agency, familiarity, flexibility, craft, delight and modern layout/material guidance.
- [Google Material 3 & Expressive](google-material3.md) — expression, salience, adaptive layouts, visual hierarchy, motion and reported research.
- [Cross-system comparative matrix](comparison.md) — Fluent, Carbon, Polaris, Adobe Spectrum, GOV.UK and other systems.
- [Vue/Nuxt component ecosystem](vue-component-libraries.md) — implementation candidates, not recommendations to install.
- [Screenshot and visual evidence guide](../visual-library/README.md) — source links, capture standards, copyright and metadata.
- [Illustrated concept exercise](../visual-library/original-studies/attention-vs-restraint.svg) — **our original diagram, not screenshots of Apple/Google**.

## Investigate systems as layered decisions
1. Principles: user purpose, tasks, contexts, responsibility.
2. Foundations: typography, color, spacing, motion, shape, elevation, content.
3. Components: anatomy, variants, states and behavior.
4. Accessibility: semantics, keyboard/focus, touch targets, contrast and reduced motion.
5. Platform adaptation: web, mobile, desktop, responsiveness.
6. Engineering: tokens, APIs, component architecture, release and migration.
7. Governance: documentation, contribution, versioning and consistency exceptions.

## Avoid false equivalence
Apple HIG is a set of platform guidance; Material is a cross-platform design system with Google implementations; Fluent/Carbon/Spectrum are enterprise/product-family systems; Shopify Polaris is optimized for Shopify app surfaces; GOV.UK is a public-service design system. Their objectives and implementation constraints differ. No system wins universally.

## Evidence labels
OFFICIAL-GUIDANCE-REVIEWED / OFFICIAL-RESEARCH-REVIEWED / CATALOG-REVIEWED are **not** LIVE-INTERACTION-TESTED. Each study must say what was actually accessed.
