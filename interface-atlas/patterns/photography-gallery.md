# Pattern 03 — Curated Photography Galleries

**Use when:** photographs preserve a meaningful shared experience, rather than only filling a commodity grid. **Status:** original conditional design brief; not a tested application pattern.

**Research sources to inspect:** Awwwards https://www.awwwards.com/, SiteInspire https://www.siteinspire.com/, existing Masterpiece Atlas, Mobbin/Refero for *real* gallery interactions. No specific external live gallery has been audited in this card.

## Visual grammar
- Give the strongest **rights-approved and truthful** hero/photo a deliberate focal position.
- Cluster images by meaningful context/collection rather than repeating equal boxes blindly.
- Use captions, time/place/creator where verified; show empty or sparse cases intentionally.
- Alternate editorial rhythm (feature vs supporting photographs) without creating an arbitrary maze.
- Distinguish featured gallery, privacy, publication and message attachment. One action cannot quietly change another's permissions.

## Interaction contract
- Browse: accessible image links and captions, keyboard/focus and lightbox behavior.
- Curation: drag/reorder or feature controls only where supported; meaningful confirm/undo.
- Source: visually distinct artist-curated photos and any future moderated fan contribution.
- Responsive: maintain semantic reading order when masonry columns collapse; avoid cut-off faces or words.
- Performance: resource dimensions, responsive image requests, LCP decisions, thumbnail strategy; measure, don't guess.
- Failure: loading placeholders, missing images, retries, alt text and meaningful gallery empty states.

**Reject if:** photographs are stunning but the user cannot find gallery actions, reorder causes privacy leaks, the phone crops faces destructively, or images degrade performance beyond accepted budget.

**Study next:** two photography/editorial layouts plus one real mobile gallery flow. Record both strength and tradeoff.
